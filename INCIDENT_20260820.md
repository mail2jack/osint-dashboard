# Incident: Junction data mass-delete — 20 aug 2026

## Wat gebeurde
De Alembic-migratie `a1b2c3d4e5f7` (CASCADE FKs op `case_subjects` / `subject_relations`)
bevatte een orphan-cleanup die via psql werd uitgevoerd zonder `SET app.tenant_id`.
FORCE RLS op `cases`/`subjects` filtered alle rows → `NOT IN (empty)` was TRUE voor
ALLE junction-rijen → **alle 22 case_subjects + 2 subject_relations verwijderd**.

## Impact
- Alle subject-case-koppelingen weg (junction tabellen leeg)
- Cases en subjects zelf intact in de DB
- Acceptatietests gebroken (test case niet meer gekoppeld)

## Herstel
1. Junction data hersteld uit `manual_20260819.dump` (pg_dump van 19 aug)
2. Test subject (`aaaaaaaa-aaaa-...`) + tweede subject opnieuw gelinkt aan TC-2026-001
3. Migratie gefixt: `SET LOCAL app.bypass_rls = 'true'` + SQLite batch mode
4. Post-recovery backup: `backups/post_recovery_20260820.dump` (498KB)

## Preventie
- Migratie fixed in commit `9e70634`: dialect-guard + bypass_rls + no-op op SQLite
- PostgreSQL integratietest toegevoegd die FORCE RLS scenario's dekt
- Nieuwe migratieregel: destructieve cleanup = pre/post-counts + abort bij onverwachte verwijderingen

## Backups
- `manual_20260819.dump` — staat voor incident (22 junction rows intact)
- `post_recovery_20260820.dump` — staat na herstel (22 junction rows + herlinking)
